# Что сейчас известно по проекту

Дата: 2026-03-24

## Общая картина
По видео и скринам разобран не один скрипт, а набор кастомных менеджеров в похожем стиле.

## 1. MTProxy / GoTelegram Manager
Признаки:
- menu-driven shell UI
- выбор fake TLS host
- выбор порта
- запуск через Docker
- вывод:
  - IP
  - port
  - secret
  - tg://proxy link
  - QR

Вывод:
Это оболочка вокруг MTProxy, ориентированная на быстрый запуск Telegram proxy для новичка.

## 2. Relay / Cascade Manager
Признаки:
- отдельное меню
- правила для TCP и UDP
- кейсы:
  - AmneziaWG / WireGuard
  - VLESS / Xray
- управление правилами:
  - добавить
  - посмотреть
  - удалить
  - сбросить всё

Вывод:
Это не VPN и не Xray сам по себе, а управляющий слой над traffic forwarding / cascade routing.

## 3. WARP Manager
Признаки:
- установка Cloudflare WARP
- регистрация / перепривязка
- локальный SOCKS5 endpoint
- показ server IP и WARP IP
- JSON для 3x-ui
- смена порта
- запуск/остановка/удаление

Вывод:
Это модуль для использования WARP как outbound transport для Xray/3x-ui/Amnezia.

## Архитектурный паттерн автора
Повторяется одна и та же идея:
- сложная технология
- + простой interactive shell wrapper
- + готовые данные для копипаста
- + минимум требований к пониманию внутренностей

## Наш вывод
Делать лучше модульную систему:
- ядро логики отдельно
- CLI отдельно
- TUI отдельно
- конфиги и state явно

## Самые вероятные первые модули
1. WARP module
2. MTProxy module
3. Relay module

## Причина такого порядка
- WARP проще как MVP
- легче валидировать результат
- меньше moving parts, чем в relay
- сразу полезен для 3x-ui / Xray сценариев
